# Development & Agent Collaboration Guidelines (CONTRIBUTING)

This repository is designed for collaborative, multi-agent, and multi-developer development during the 48-hour NASA Space Apps Challenge 2026. All human contributors and autonomous AI agents (Claude Code, Google Antigravity, OpenAI Codex, Cursor, Windsurf) must follow these protocols.

---

## 1. Golden Rules for Autonomous Agents

1. **Adhere to the Telemetry Contract:**  
   All data structures exchanged between the Rust backend (`ares-engine`) and the React frontend (`ares-cockpit`) must conform strictly to [contracts/telemetry_schema.json](./contracts/telemetry_schema.json). Never alter telemetry key names or units unilaterally.
2. **100% Offline / Air-Gapped Operation:**  
   Deep space simulations execute with zero Internet access. Do not write code that fetches external cloud endpoints at runtime. All WebSockets, FastMCP transports, and HTTP endpoints must bind strictly to `localhost` or `127.0.0.1:8080`.
3. **Safe Rust 2024 Invariant:**  
   The core engine must be written in 100% Safe Rust (`#![forbid(unsafe_code)]`). Never introduce `unsafe` blocks. Handle all errors explicitly using `Result` or `Option` (no uncontrolled `.unwrap()` in message loops).
4. **OLED Dark Aesthetic `#000000`:**  
   All frontend UI code must use pure black backgrounds (`#000000`) for microgravity power efficiency and dark adaptation, with aerospace-standard amber (`#F59E0B`), cyan (`#06B6D4`), and warning red (`#EF4444`).
5. **No Emojis:**  
   NASA aerospace engineering standards forbid emojis across codebases, commit logs, and technical documents.

---

## 2. Git Branching & Workflow

To enable 5 team members and their AI agents to work simultaneously without merge conflicts:

* `main`: Protected production branch. Code merged here must build cleanly with zero warnings.
* `feat/backend-telemetry`: Development of `ares-engine` (Rust, Tokio, Frost-Hargens ODEs, FastMCP).
* `feat/frontend-cockpit`: Development of `ares-cockpit` (React, TypeScript, Tailwind, WebSocket hook).
* `feat/3d-mannequin`: Development of the WebGL Three.js anatomical deconditioning view.
* `feat/data-pipeline`: Python telemetry generators, PhysioNet / NASA OSDR parameter extractors.
* `docs/nasa-submission`: Video pitch script, slide deck PDF, and submission portal deliverables.

---

## 3. Commit Message Standard (Conventional Commits)

All commits generated by agents or developers must follow the `git-standard` skill:

```text
<type>(<scope>): <short imperative description>

[optional body explaining technical motivation and equations]
```

Allowed types:
* `feat`: New feature or system capability.
* `fix`: Bug fix or numerical correction.
* `math`: Update to differential equations, ODE solver, or STL robustness logic.
* `medops`: Update to clinical action DAGs, POCUS ultrasound guides, or LBNP protocols.
* `perf`: Performance optimization (e.g. zero-copy parsing, SIMD vectorization).
* `docs`: Documentation, architecture diagrams, or submission guide updates.
* `test`: Unit tests, mock telemetry fixtures, or property-based tests.

---

## 4. Cross-Agent Verification Checklist

Before opening a pull request or merging a feature:
- [ ] Run `cargo test` inside `ares-engine/` and verify all tests pass.
- [ ] Run `npm run build` inside `ares-cockpit/` with zero TypeScript errors.
- [ ] Validate sample JSON output against `contracts/telemetry_schema.json`.
- [ ] Confirm no emojis or external API URLs have been introduced.
